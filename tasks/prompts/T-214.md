### Goal
- A dropped connection during a resume doesn't strand the character.
- Characters in their grace period can't push the server past its session limit.
- Bandwidth gets cheaper where a measurement proves it helps.
- A load test produces real numbers.

### Requirements
1. **Token acknowledgement.**
   - After a resume, the previous token stays valid only until the client's **first message on the new session**, which is an implicit
     acknowledgement. It never outlives the grace period.
   - Each token is still single use.
   - Test it: a drop between the resume and the new `welcome` is resumable with the old token; after the first message it is refused.
2. **Grace cap.**
   - Characters in grace count toward `max-sessions`.
   - A login on a full server is refused with a `bye` reason, never by evicting someone.
   - A resume of an existing character is always allowed.
3. **Load test.**
   - A scripted client that logs in N bots, walks them and makes them fight (T-307 messages). It reports per-client KB/s, server tick
     p50/p99 and server memory.
   - Run it with 50 and 200 bots, and with 100 characters in grace.
4. **Warp/disconnect removal.** Fix the case T-205 found in the world: a disconnect during a cross-map warp loses the removal. Then
   delete the re-despawn workaround in the gateway.
5. **Compression.**
   - Implement permessage-deflate behind a setting.
   - Measure it with the load test.
   - Enable it by default only if it saves ≥ 30% bandwidth for < 1 ms/tick extra CPU at 50 bots.
   - Shared serialized delta pieces only if the sink cost exceeds 2 ms/tick at 100 observers; otherwise report the number and don't
     build them.
6. **Warm-up and catch-up.**
   - Report tick p99 **after warm-up** in the load test. If a combat tick still goes over 50 ms after warm-up, warm the hot paths at boot
     with one scratch-instance combat tick (ADR-002 row 100).
   - Document in ARCHITECTURE §10 that `hits` are dropped while a client catches up, and that the following snapshot restores state
     (row 101).
