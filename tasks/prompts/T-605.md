### Goal
A player ticks one or more quests, switches autopilot on, and can always see that it is on, what it is doing, and why it paused or stopped.

### Requirements
1. **Ticking.** In the quest log, each active quest has an autopilot tick. Ticked quests show their run order, and it can be changed (say how, and why that way on a phone). Ticks for quests that are completed or abandoned go away. Ticks are this player's own and are not sent until the start.
2. **Start and stop.** A Start button in the log sends `start_autopilot` with the ticked quests in order and the skills in the shortcut slots in slot order. Stop sends `stop_autopilot`. Start is disabled with nothing ticked or while dead; the server still decides. Every refusal shows its reason.
3. **On the HUD.** While a run is on or paused: a compact indicator (48 dp target) with what it is doing and the current quest; a tap stops it. Paused shows the reason, as something the player can act on ("Reach level 10 to go on"). When a run ends, the flash line says why. Off shows nothing.
4. **Only the server's word.** The client decides nothing: the state comes from `autopilot` messages only, is cleared on logout and refreshed after a resume. Do not send automatic messages that count as manual input (`dialogue_close`, `stop` and the like) while a run is on: check the dialogue, shop and targeting code for them, and test it.
5. **Manual input ends a run** (T-604). Make that visible, not surprising: the flash line says so. The dialogue panel opened by the autopilot must not block the HUD indicator.
6. **Phone layout.** The indicator must not overlap anything in T-408's `-Run ui` check; add it, and the ticks and buttons in the log, to the matrix with the longest words. All words in `UiText`. Draw calls and allocations within §9: say how measured.
7. **Tests.** The view model (ticks, order, removal, messages, refusals, reset); `ClientSession` sends and receives; the longest texts. One scripted e2e run: accept First Hunt, tick, start, see it run, see the turn-in happen with no manual input, see `finished`; then start again and tap to stop, and walk to end it by manual input.
