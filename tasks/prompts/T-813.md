### Goal
The owner asked (2026-11-28) for a way to generate the game's sounds with an AI tool, so the default theme gets real sound effects, ambience and music (T-306) without a sound designer. This task builds the **pipeline and the prompt sheet**; generating the final sounds is a step the owner runs.

### Requirements
1. **The list of sounds**: read every audio asset key the theme's manifest and the content use (34 today: `sfx.*`, `ambience.*`, `music.*`), and keep a sheet in the theme (for example `themes/default/audio/sounds.yaml`): per key, a short text prompt in plain words (what it is, mood, length, loop or not), its kind, target length, and whether it loops. Original descriptions only: never "like <a named game>" (CLAUDE.md: original names and art only). Write a good first prompt for every key.
2. **Back-ends** behind one small interface in a tool (for example `tools/soundgen`), chosen by an option:
   - `audiogen`: Meta AudioCraft's AudioGen, run locally on this PC (free, open source). The tool says how to install it and its model, and **does not download anything by itself**: if the package or model is missing it stops and prints the one command for the owner to run.
   - `elevenlabs` (or another hosted sound-effects API the owner picks): reads its key from an environment variable only, never from a file in the repository, never printed or logged; the tool refuses to run without it. The owner creates the account and the key.
   - `placeholder`: makes plain synthesized sounds (tones, noise bursts) with no network and no model, so the whole pipeline and its tests run anywhere, including CI.
   - Music: note which back-end can make loops, or say that music needs another tool (for example a music generator) and leave its keys to the `placeholder` until the owner chooses one.
3. **After generating**: trim silence, normalise loudness to a target in the sheet (say which, for example around -16 LUFS for effects), fade loops so they loop without a click, convert to the format and sample rate the client already uses, keep each file within a size budget (say which, against ARCHITECTURE §9 and the app size), write it under the theme's `audio/` and point the manifest key at it. Generate several variations per key on request and keep the chosen one.
4. **Licence record**: every generated file gets a line in a record next to it (back-end and model or service, its version, the prompt, the date, and the licence terms that applied: the owner confirms commercial use is allowed for their plan). ThemeCheck (or `validate`) fails a theme whose audio file has no record. `docs/THEMES.md` says plainly that the owner must check the service's licence before publishing.
5. **Review**: a local page or a report listing each key with a player for its file, its prompt and record, so the owner can listen and choose. Loopback only; no window opened on the owner's screen by the tool's own runs.
6. **No game code changes**: sounds are reached only by asset key (rule 3). If a key the content uses has no sound, the theme check says so as today.
7. **Docs**: `docs/THEMES.md` (generating sounds, the back-ends, the licence step), the T-306 row in `docs/TASKS.md` noting this tool, ADR-002 rows from 540.
8. **Tests**: the sheet covers every audio key the content and manifest use; the `placeholder` back-end makes every key; post-processing gives the target loudness, length, loop fade, format and size; a file without a licence record fails the check; the hosted back-end refuses to run without its key and never writes the key anywhere; nothing is downloaded by the tool.
