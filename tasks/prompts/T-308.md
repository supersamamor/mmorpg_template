### Goal
This task fixes three gaps left after T-301 and T-302:
- HP and SP come back over time;
- a dead monster stays visible long enough for its death animation;
- monsters can no longer walk off their map through a warp.

### Requirements
1. **Natural regeneration.**
   - Players and monsters regenerate the derived stats `hp_regen` and `sp_regen` (points per second) in simulated time, never above max.
   - Regeneration pauses for a `balance.yaml` out-of-combat delay after the entity deals or takes damage.
   - The dead never regenerate.
   - Accumulate fractions without drift, with no allocation per tick.
2. **Monster returns home.** A monster that gives up and returns home heals to full on arrival if `balance.yaml` `ai.heal_on_return` is
   true; the default is true, with a comment. Its damage-share table resets, so EXP from a later kill isn't split with old attackers.
3. **Corpse time.**
   - After `EntityDied`, a dead monster stays in the world, `Dead` and not targetable, for `balance.yaml` `death.corpse_ms` milliseconds,
     so clients can play the death animation. Then it is despawned.
   - The respawn timer still counts from the death tick, as documented.
   - If the spawner's despawn-on-death behaviour changes, update ARCHITECTURE §6.6.
4. **Warps are for players.** Only `EntityKind.Player` triggers warps. Other kinds walk over warp cells as normal walkable cells. Test it,
   including a wandering monster crossing a warp cell.
5. **Small fixes from T-302** (ADR-002 rows 79, 81–83). For each one you may touch `src/Game.Shared/Stats/**`,
   `src/Game.Shared/Progression/**`, `MapDef` with its rule and schema, and `content/maps/*.yaml`.
   - **`StatSheet.WriteTo(asTarget: true)` allocation:** it builds `t_` names on every call. Resolve the target-side slots once. The
     existing allocation pin becomes `0`.
   - **AI sentinel overflow:** the T-301 AI uses `long.MinValue` for "no move issued yet", and `tick - long.MinValue` overflows. Replace
     it with an explicit flag, and add a regression test for a monster's first move.
   - **`ProgressionRules.LoseBaseExp(state, amount)`:** it never goes below 0 within the current level and never loses a level. It returns
     the amount lost. Add golden tests, and make the combat death penalty call it instead of editing `BaseExp`.
   - **Per-map respawn point:** an optional `respawn` cell on `MapDef`, validated as walkable on the map's grid. A player who dies
     respawns there. Without it, the fallback is the map's first arrival warp cell, then `new_character`. Set it for both sample maps.
6. **Data and tests.** Every new number lives in `balance.yaml` with a comment, is validated, and has its schema regenerated. Tests use a
   fake clock and cover:
   - regeneration rate;
   - the out-of-combat pause;
   - the cap;
   - heal on return (on and off);
   - the damage-share reset;
   - corpse time and respawn timing;
   - warp kinds.

   Add the regeneration cost to the existing combat cost log, and assert bounded allocations.
