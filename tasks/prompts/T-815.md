### Goal
The owner asked (2026-11-28): "the skill slot at the bottom should be draggable to interchange the skill slots's skill". Today the skill bar is the learned active skills in tree order, with no way to change it.

### Requirements
1. **Drag to swap.** Drag a skill from one slot onto another to swap them; onto an empty slot to move it there. Touch first (phones, landscape): decide how a drag starts so it never fires a skill by accident and a quick tap still uses the skill exactly as today (for example a long press, then drag), and how a cancelled drag looks. Mouse works too in development builds. A drag while a skill waits for a target tap cancels that wait first.
2. **The order is the player's, per character, kept on the device** with the other preferences (no server change: the server never needed the bar's order; quest autopilot and auto-battle already get the skills "in slot order" from the client, so they follow the new order: say so and test it). Decide and say: where a newly learned skill goes (the first empty slot, for example), what happens to a slot whose skill is forgotten by a skill reset (T-503) or no longer exists in content, and what a new device shows (tree order, as today).
3. **Feedback**: the dragged skill follows the finger; the slot under it is lit; dropping outside the bar cancels. Cooldowns keep running on the skill, not the slot.
4. **Optional, decide:** dragging a skill from the Skills panel onto the bar. If you leave it out, list it as a follow-up.
5. **Layout**: the drag states in the `ui` matrix with 0 problems on every screen, notch and UI scale (the smallest phone at the largest scale included), with no new allowance in the layout check. Say how you measured against ARCHITECTURE §9 (no allocation per frame while dragging, if you can show it).
6. **Docs**: ARCHITECTURE (hotbar), VOCABULARY if a term is added, ADR-002 rows from 560.
7. **Tests**: swap and move in the model; a tap is still a press; the order is kept and restored per character; learning, resetting and a vanished skill as decided; the autopilot's skill list follows the order. Extend the `skills` (or `ui`) e2e run: a scripted drag swaps two slots, and the swapped order survives a reconnect.
