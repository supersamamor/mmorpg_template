### Goal
After loading, a validator checks every rule in ARCHITECTURE.md §5.1, and `Game.Tools validate` runs it with CI-friendly output and exit codes.

### Scope — files you may create or change
- `src/Game.Content/Validation/**`
- `src/Game.Tools/Commands/ValidateCommand.cs`
- `tests/Game.Tests/Validation/**`

### Out of scope — do not touch
- Formula semantic checks beyond 'parses' (handled with T-103 integration)

### Requirements
1. Rule-based: each check is an `IValidationRule` class; easy to add more later.
2. Rules: referenced ids exist (job→skills, skill prereqs, items→statuses, monsters→drop tables, drops→items, quests→monsters/items/npcs, npcs→dialogue, maps→monsters/npcs); vocabulary membership (stats, elements, slots, effect types, objective types); asset keys exist in the active theme manifest; skill tree prerequisites are acyclic; job parent chain is acyclic.
3. `validate [--content <dir>] [--theme <name>] [--format text|json]`. Exit 0 clean, 1 errors. Text output groups by file.
4. Warnings (non-fatal) for: unused items/statuses, monsters never spawned, skills not in any job tree.
5. Tests: one fixture per rule proving it fires.

### Acceptance criteria
- [ ] `dotnet build` passes with zero warnings (`TreatWarningsAsErrors` on)
- [ ] `dotnet test` passes
- [ ] `validate` on sample content exits 0
- [ ] Renaming one item id in a quest reward makes `validate` exit 1 naming the file and path
