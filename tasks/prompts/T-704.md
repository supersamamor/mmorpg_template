### Goal
The character-creation options from ARCHITECTURE §7.5.1 exist as **content**: `content/appearance.yaml` defines, per gender
(**male**, **female** — the owner's chosen labels), the body model, faces and hairstyles, plus shared skin-tone and hair-colour palettes
and a default look. The loader reads it, `validate` checks it, a schema is generated, and the client bundle carries it (the creation
screen needs it). The server-side creation flow (T-705) and the screen (T-706) come later.

### Requirements
1. **`AppearanceDef`** (`sealed record`, XML docs, singleton root file `appearance.yaml`, required):
   - `genders`: exactly the `Genders` terms, each with `body_model_asset_key` (`model.*`), `faces` (id, name, asset key) and `hairstyles`
     (id, name, `model.*` asset key), and a `default` (face, hairstyle).
   - `skin_tones` and `hair_colors`: id, name, `color` as `#RRGGBB`; a default for each.
   - Option ids are namespaced strings with your new prefixes; names are display text.
   Cosmetic only — no stat or rule fields, and say so in the XML doc.
2. **Validation:** every gender term present exactly once; unique ids with the right prefix; every asset key exists in the active theme
   manifest; each face/hairstyle model uses the **same rig** as its gender's body (read the manifest's `rig` metadata; hairstyles attached at
   the `head` attach point may have no rig — define and document the rule); colours are valid hex; every list non-empty; defaults reference
   existing options of that gender. Errors name `appearance.yaml` and the path.
3. **Client bundle:** include the whole appearance definition (ids, names, asset keys, colours). Leak tests stay green.
4. **Sample content:** original names; 2 genders; 3 faces and 4 hairstyles per gender; 6 skin tones; 6 hair colours. Point models at placeholder
   files like the existing entries, with the correct `rig` metadata (`humanoid` bodies; check what rigs the manifest already uses).
5. **Tests:** sample loads; each validation error (missing gender, duplicate id, wrong prefix, unknown asset key, rig mismatch, bad colour,
   empty list, bad default); bundle contains the options; schema generated and mapped in `.vscode/settings.json`.
