### Goal
The client draws entities from the active theme through asset keys, instead of hardcoded capsules. A generated placeholder pack means every key in the manifest resolves to a real glTF file, so the whole path works before real art exists, and swapping a theme needs no code change.

### Scope
- `client/**`, except the HUD and input files, which T-211 will change later. Implement the existing `IEntityVisualSource` seam.
- `themes/default/**`: the placeholder pack (Git LFS, per `.gitattributes`) and the manifest
- A generator script for the pack under `tools/`, so it can be rebuilt. Use a tool `setup-prereqs.ps1` already installs, or plain C#/node writing glTF.
- `tests/Game.Tests/**`, `docs/ARCHITECTURE.md` §7.7 and §8, `docs/MOBILE_BUILD.md` if export steps change, `docs/TASKS.md` (this row only)

### Out of scope
- Real art; authored map scenes (T-208); modular equipment (T-403); audio playback (T-305); damage numbers and VFX (T-303)
- `src/**` other than theme validation you can't avoid, and `content/**` other than asset keys that turn out to be missing. If a key is wrong, list it.

### Requirements
1. **Manifest loader (pure, in `client/Core`, tested).** Parses the manifest, resolves keys to theme files, and has a defined fallback chain from §8 for a missing key: a visible "missing asset" placeholder and one logged warning, never a crash. No asset paths in code or content (hard rule 3).
2. **Theme mounting.** The active theme comes from client settings, default `default`. Follow §7.7. A second minimal test theme proves that swapping changes visuals with no code change.
3. **Generated placeholder pack (row 31).** Every key in the manifest gets a file. Characters and monsters are low-poly rigged glTF with idle, walk, attack, hit and die clips, using the shared rig from §7.5–7.6, and each carries its key's name or a distinct colour so they are tellable apart. Meet §9: LOD0 ≤ 5k and LOD1 ≤ 2k triangles, 1 material, textures ≤ 1024².
4. **Entity visuals.** `display_key` → bundle → asset key → pooled scene instance. Animation state follows the view model: idle, walk, dead, and a one-shot attack and hit on `hits`. Apply the §9 LOD rule: nearest 8 at LOD0, the others at LOD1. Past 40 animated characters, use a reduced animation rate.
5. **Loading.** Assets load without a visible stall on a map change, and a warp or first appearance doesn't hitch. Keep memory bounded; say how.
6. **Keep the end-to-end run.** `client/run-e2e.ps1` must still pass, headless and windowed, against real content.
7. **Tests** in `tests/Game.Tests/Client/`: manifest parsing, fallback chain, LOD selection, and a check that every asset key used by the content bundle exists in the default manifest and on disk.
