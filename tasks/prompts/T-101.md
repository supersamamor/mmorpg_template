### Goal
`Game.Content` loads every YAML file in a content root into typed, read-only registries, with precise error reporting (file + line + path) on parse/shape errors.

### Scope — files you may create or change
- `src/Game.Content/Loading/**`
- `src/Game.Content/Registry/**`
- `tests/Game.Tests/Content/**`

### Out of scope — do not touch
- Cross-reference validation (T-102)
- Formula parsing (T-103)

### Requirements
1. `Registry<T>` keyed by id: `Get(id)` (throws with helpful message), `TryGet`, `All`, `Count`. Immutable after build.
2. `ContentDatabase` aggregates all registries + `FormulaSetDef`, `ElementTableDef`, `ExpTableDef`.
3. `ContentLoader.Load(string root) → LoadResult { ContentDatabase?, IReadOnlyList<ContentError> }`. Collect **all** errors, don't stop at the first.
4. `ContentError` has `File`, `Line`, `Column`, `Path` (e.g. `effects[1].formula`), `Code`, `Message`.
5. YamlDotNet with underscored naming convention; strict: unknown keys are errors.
6. Polymorphic effects/objectives/rewards deserialize via the `type` discriminator.
7. Duplicate ids and wrong prefixes are load errors.
8. Tests: load `/content` successfully; malformed fixtures under `tests/Game.Tests/Fixtures/bad/` produce the expected errors with line numbers.

### Acceptance criteria
- [ ] `dotnet build` passes with zero warnings (`TreatWarningsAsErrors` on)
- [ ] `dotnet test` passes
- [ ] Loading the sample content has zero errors
- [ ] A file with an unknown key reports file + line
