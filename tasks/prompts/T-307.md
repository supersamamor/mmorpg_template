### Goal
A real client can fight. T-302 built combat inside the server world. This task lets players:
- send attack and respawn intents;
- see HP bars, hits, misses, deaths and drops around them;
- see their own EXP and level changes.

All of this stays within the 10 KB/s budget, and nothing secret reaches the client.

### Scope

### Requirements
1. **Client messages.**
   - `attack {target}` → `AttackTarget`; `stop_attack` → `StopAttack`; `respawn` → `Respawn`.
   - Each goes through the session token bucket and is validated: the target must be an entity id the session can currently see.
   - A refusal comes back as `rejected` with a vocabulary reason, like `move`.
2. **View records.**
   - Monsters and players carry `hp` as a fraction 0–1, rounded to 1/100, so exact HP of others never leaks. It is sent only when it
     changes.
   - Ground items appear as kind `item` with item id and quantity, and **no** owner or loot-timer details. A client is only told whether
     it may pick the item up now (`mine: true/false`).
   - A dead entity has a `dead` flag.
3. **Event messages to observers.**
   - A compact `hits` batch per tick for entities in the observer's view: attacker, target, amount, flag (hit/crit/miss).
   - Deaths come through the `dead` flag.
   - Batch per tick per observer and reuse buffers as T-204/T-205 do.
4. **Owner-only messages.**
   - Exact own `hp/max_hp/sp/max_sp` when they change.
   - `exp` (base and job, current and next level requirement) and `level_up`.
   - `you_died`, and the respawn result.
5. **Budget.**
   - Measure the 50-visible-entity test from T-204/T-205 with continuous combat: 20 players fighting monsters.
   - Report KB/s per client, and stay ≤ 10 KB/s.
   - If it is over, apply in this order: short keys, then dropping unchanged fields, then rate-limiting `hits` to observers more than N
     cells away. Report what was needed.
6. **Hostile client.**
   - Fuzz the new messages: unknown target, a target out of view, attacking yourself or a player, a flood (rate limit), malformed JSON.
   - None may crash a session or the instance.
7. **Tests.**
   - Protocol golden JSON for each new message.
   - An end-to-end gateway test: log in, attack a meadow monster until it dies, see `hits`, the `dead` flag, the drop and `exp`.
   - A resume mid-fight.
