### Requirements
1. **Attach and skin.** Resolve each worn item's `visual_asset_key` from the display bundle through the theme chain (§7.7). An `attach` entry goes on that bone of the character's rig. A `skinned` entry is bound to the character's skeleton, so it plays the same animation. A missing or wrong key falls back as §7.7 says (the theme's missing model), with one warning per key, never a crash. A missing bone falls back to a documented default point and warns once.
2. **Changes.** Re-dress only when the entity's worn change counter moves, not every frame. Equip and unequip swap only the changed pieces. Two-handed weapons look right with the shield slot empty (ADR-002 row 170).
3. **Animation.** The weapon type picks the attack and idle clips where the theme's animation library has them (§7.6), with a fallback to the generic ones. Hit timing stays T-303's `impact_delay`.
4. **Loading (row 141).** Equipment models load the way character models do: on the main thread when headless, threaded with a real renderer, and cached and shared between characters wearing the same item.
5. **Budget (§9, row 164).** Measure draw calls and triangles with 40 fully equipped characters fighting (`tools/loadtest --spare-slots`, with bots given gear if the load test can do that without server changes; otherwise say how you measured). Attached pieces add draw calls, so report the cost per character and keep the crowd peak under 100. If you can't, say what it would take.
6. **Placeholders.** If the generated placeholder equipment can't show attach and skinning, extend `themegen` so it can (still placeholders, original shapes), and keep `themegen --check` clean.
7. **Tests.** Attach-or-skin choice from the manifest, the fallback chain for missing keys and bones, re-dress only on a counter change and only the changed pieces, the two-handed case, clip choice by weapon type with fallback, and the cache sharing one resource per key.
