### Goal
This repo is a **template**. It keeps its generated placeholder theme; each game made from it is a fork that adds its own theme. Make applying a theme in a fork cheap and mostly mechanical:
a written contract, an import tool driven by a small mapping file, and a fork guide.

### Requirements
1. **Theme contract** (a new `docs/THEMES.md`, linked from ARCHITECTURE). It says exactly what a theme must provide for each asset key kind:
   - the rig and bone names (one shared humanoid rig, so gear and appearance can attach);
   - the required animation names and loops;
   - scale (1 cell = 1 unit) and facing;
   - weapon and gear attachment points;
   - the §9 budgets per asset (triangles, texture size, materials);
   - how the toon material and outlines from T-222 apply to imported models.

   ThemeCheck must check every rule that can be checked, with a clear message per failure.
2. **Manifest variants.** One model can serve several keys. A manifest entry may point at another entry's model with a `tint`, a `scale` and an optional `outline` override. Examples are a recoloured monster or an elite version. Add validation and tests, and use it in the placeholder theme for at most one example.
3. **Import tool** (`tools/themeimport` or a `themegen` subcommand). It reads a mapping file (YAML) that lists, for each asset key:
   - a source file in a pack folder;
   - scale and facing fixes;
   - animation renames;
   - the attachment bone;
   - an optional variant.

   It then writes the theme folder and manifest, runs ThemeCheck and prints a report: done, missing keys, rule failures with fixes.
   - It must be **idempotent**: running it twice changes nothing.
   - Pack files are never committed. Theme folders created for evaluation go under a git-ignored path (add the ignore rule).
4. **Fork guide** (`docs/FORKING.md`):
   - how to fork and apply a theme;
   - monsters are matched by role, not name;
   - keep the ids and change only display names; adding or removing monsters is data, and the balance golden tests to update are listed;
   - the licence notes: CC0 vs paid packs, and never committing paid source files.

   Include a role table of every current monster, NPC and the player character, so a fork can map a pack quickly.
5. **Testing without downloads.** Test the tool on a small synthetic pack that the test itself generates (glTF written in code, with wrong scale, facing and animation names). **Do not download any pack.** A real-pack trial needs the user's approval and comes later.
