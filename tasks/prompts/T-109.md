### Goal
A singleton `BalanceDef` loaded from `content/balance.yaml`. It holds the tuning numbers and
small formulas that are not per-entity stats: stat and skill point awards, stat point cost, caps,
and combat clamps. T-105 (progression) and T-106 (combat) read their numbers from it, so no
balance number ends up in C#.

### Scope — files you may create or change
- `src/Game.Shared/Definitions/BalanceDef.cs` (new), plus registering it wherever definition types
  are listed (e.g. `FormulaSources`, `FormulaSymbols` in `src/Game.Shared/Formulas/` for new variables)
- `src/Game.Content/Loading/**`, `src/Game.Content/Registry/ContentDatabase.cs` (root file, singleton)
- `src/Game.Content/Schema/**`, `schemas/balance.schema.json` (generated), `.vscode/settings.json`
- `src/Game.Content/Validation/**` (balance formulas checked by `FormulaRule`; caps/ranges sane)
- `content/balance.yaml` (new), `content/README.md`
- `docs/VOCABULARY.md` (any new formula variable), `docs/ARCHITECTURE.md` §5.2 and §6.5 (one line each)
- `tests/Game.Tests/**` (new tests for this task only)

### Out of scope — do not touch

### Requirements
1. `BalanceDef` is a `sealed record` like `FormulaSetDef` (singleton, no id), with XML doc comments,
   in two sub-blocks:
   - `progression`: stat points awarded per base level up (formula of `base_level`), skill points
     awarded per job level up (formula of `job_level`), starting stat points, starting value of each
     primary stat, max primary stat value, stat point cost to raise a stat by one (formula of the
     stat's current value; add a whitelisted variable for it, e.g. `stat_value`), max base level.
   - `combat`: minimum damage, maximum damage, hit chance min/max, crit chance min/max (chances as
     0–1 or 0–100 — pick one, document it, and match what `formulas.yaml` returns).
   Check the existing records first: if a cap already lives elsewhere (e.g. job max level on
   `JobDef`, or the length of an EXP table), don't duplicate it. Say what you found.
2. All formula fields are strings compiled by the T-103 evaluator. Add them to `FormulaSources`
   so `FormulaRule` checks them. Use narrowed symbol sets where the field only makes sense with
   certain variables (e.g. stat point cost may only use `stat_value`).
3. The loader reads `balance.yaml` as a required root file. The validator rejects nonsense ranges
   (min > max, negative caps, max primary stat < starting value).
4. Regenerate schemas with `dotnet run --project src/Game.Tools -- schema` (the staleness test must
   pass) and map `content/balance.yaml` in `.vscode/settings.json`.
5. `content/balance.yaml` with original, sensible numbers for the Lumen Vale sample (levels 1–99,
   stats 1–99). Put a comment on each value explaining the intent.
6. Tests: the sample loads with the expected values; a bad range is a validation error naming
   `balance.yaml` and the path; an unknown variable in a balance formula is an error.
