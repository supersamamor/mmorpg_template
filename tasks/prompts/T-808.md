## Prompt (summary of the lead's request)

You are working on task **T-808** in this repository.
Read `CLAUDE.md`, `docs/ARCHITECTURE.md`, and `docs/VOCABULARY.md` first and follow them.

### Goal
Find and fix the intermittent test failures recorded in ADR-002 rows 450, 470, 488 and 497.

### Requirements
1. **First:** `Accounts.DatabaseTests.No_session_survives_a_password_change_that_races_its_sign_in`
   (failed in three lead checks, about 1 run in 7 under load). Make it fail on purpose (loop the
   Accounts, Trade and Saving classes together under a CPU load generated in the run), capture
   the assertion message, and decide whether it is a real race or a wrong test. Read
   `TryAddSessionAsync`, `TryChangePasswordAsync` (both lock the account row `FOR UPDATE`) and
   `RunAsync`'s retry on transient errors (a retried commit could report a wrong result).
   A real race is a security bug: fix the code and explain it in a new ADR-002 row.
   Check the sibling `No_session_survives_a_deletion_that_races_its_sign_in` (row 488) the same way.
2. `Saving.CharacterSavingTests.Stacks_count_too_and_picking_up_your_own_needs_nothing`: a save can
   land before the test checks the link between the two characters; wait for the right state,
   not a fixed time.
3. `Trade.TradeDatabaseTests` class clean-up: close its connections (or clear the pool) before
   dropping its database.
4. `Admin.AdminApiTests.Kick_ends_the_game_and_every_session_and_the_player_signs_in_again`
   (row 470): find its timing assumption and fix it.
