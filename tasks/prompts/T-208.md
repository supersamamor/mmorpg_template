### Goal
A designer builds a map as a 3D scene in the Godot editor, presses a button, and gets a valid `content/maps/<name>.grid.json`. `validate` fails if the scene changed after the last export. The client shows the real scene through the `IMapView` seam, so both sample maps come from authored scenes instead of ASCII art.

### Scope
- `client/addons/map_authoring/**` (new editor plugin; C# or GDScript, your choice, say why)

- `src/Game.Content/**` and `src/Game.Tools/**` for the staleness check, `tests/Game.Tests/**`, `docs/ARCHITECTURE.md` §5.3, a new authoring guide in `docs/`, `docs/TASKS.md` (this row only)

### Out of scope

### Requirements
1. **Bake.** One downward ray per cell against the scene's collision shapes, with a slope limit from plugin config. Deterministic: same scene, same grid. Rays must not depend on the editor camera or the current selection.
2. **Paint overrides.** A designer can force cells walkable or blocked, and mark `blocks_los`, with an in-editor grid overlay. Overrides are saved in the scene, so a re-bake keeps them.
3. **Markers.** Spawn, warp, NPC and zone marker nodes with metadata that reference content ids, as §5.3 says. The export writes them with the grid; a marker on a blocked cell or naming an unknown id is an error shown in the editor.
4. **Export without the editor UI.** A headless command exports one or all maps, so CI and tests can run it. The output is canonical, so a re-export with no change gives identical bytes.
5. **Staleness (§5.1).** Export stores `source_scene_hash`. `validate` fails, with file and path, when a scene's hash differs. The hash covers what affects the grid, and is stable across machines and line endings. `validate` must not need Godot: it reads the hash from the scene files. If that's impossible for binary resources, say so and propose the alternative. CI must keep working without Godot on the fast job.
6. **Sample maps.** Author `starter_meadow` and `thistle_hollow` as scenes and export them. **Keep gameplay the same:** width, height, walkable cells, spawns, warps, NPCs and zones should match the current grids exactly. If an exact match isn't reasonable, list every difference and why. Golden and server tests must still pass without loosening them.
7. **Client.** `IMapView` loads the scene through the asset key and the theme, keeping T-207's fallback chain: a missing scene falls back to `PlaceholderMap` with one warning. Entities stand on the terrain by raycast (§4), so visual height doesn't change the simulation. Stay within §9.
8. **Guide.** A short `docs/MAP_AUTHORING.md`: how to make a new map, start to finish.
9. **Tests.** Bake determinism, override survival, marker validation, canonical output, staleness pass and fail, grids matching the schema. Keep the pure logic testable without Godot where possible.
