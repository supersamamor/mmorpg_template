### Goal
- The server and `validate` load and check content the same way.
- Ticks start on time on Windows.
- Each map instance reports its tick timings, ready for the admin panel.
- Two missing tests get written.

### Scope
- `src/Game.Server/Hosting/**`, `src/Game.Server/World/**` (tick loop and counters only), `src/Game.Server/Program.cs`
- `src/Game.Content/**`: a shared `ContentBoot` (load, validate with theme manifest and audio data)
- `src/Game.Tools/**`: use the shared boot
- `tests/Game.Tests/**`, `docs/ARCHITECTURE.md` §3, `docs/TASKS.md` (this row only)

### Out of scope
- `src/Game.Server/Net/**`, `Persistence/**`, `Admin/**`, `content/**`, `content/formulas.yaml`
- Changing tick order or any system's behaviour

### Requirements
1. **One content boot.**
   - Move load, validate and theme-manifest loading into one `Game.Content` entry point, used by both `ServerBoot` and `validate`.
   - The server boot now also runs the manifest's audio checks (T-304). An error refuses to start, with the same text `validate` prints.
2. **Tick precision on Windows.**
   - Use a high-resolution waitable timer (`CreateWaitableTimerExW` with `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION`), with a short spin for
     the last ≤ 1 ms, or an equivalent.
   - Use the current wait on other operating systems.
   - Keep simulated time derived from the tick count; this changes when a tick starts, not what it simulates.
   - Log the start lateness before and after: p50 and p99 over 600 ticks.
3. **Tick statistics.**
   - Each `MapInstance` keeps a fixed-size ring buffer of recent tick durations, and exposes p50, p99 and max plus the existing counters
     as a read-only snapshot, safe to read from another thread.
   - No allocation per tick.
   - The admin panel (T-804/T-805) will read it later. Add no API endpoint here.
4. **Tests.**
   - **AOI crowd:** a crowd of observers crossing bucket boundaries while other walkers cross theirs. Every observer's view equals a
     brute-force "within view window" set after every tick.
   - **Shutdown:** a boot test that starts `Game.Server` as a process with `--duration`, and another that sends Ctrl+C (or the platform
     equivalent). Both exit 0 and log a clean shutdown.
   - Put timing-dependent tests in the non-parallel collection.
