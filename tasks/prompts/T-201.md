### Goal
Every `MapDef` has a loaded, validated logic grid. The grid file format (`content/maps/<name>.grid.json`)
is defined by a C# record with a generated JSON Schema, loaded next to its map, and exposed as an
immutable, allocation-free `MapGrid` that later tasks query (pathfinding T-203, tick loop T-202,
spawns T-301). Until the Godot exporter exists (T-208), sample grids are produced from ASCII
art by a small tool command.

### Requirements
1. **File format** (`MapGridFile`, a `sealed record` with XML docs, schema generated like the other defs):
   - `format_version` (int, starts at 1; the loader rejects unknown versions), `map_id`, `width`, `height`.
   - `cells`: base64 of one byte per cell, row-major (`index = y * width + x`, `(0,0)` is the north-west corner,
     `+x` is east, `+y` is south — say this in ARCHITECTURE §5.3 and match §4's world mapping).
     Bit `i` is the `i`-th term of `CellFlags.All` (bit 0 `walkable`, bit 1 `blocks_los`); other bits must be 0.
   - `source_scene_hash` (string, may be empty until T-208).
   - `spawns`: monster id, area rect (x, y, w, h), count, respawn seconds.
   - `warps`: cell (x, y), target map id, target cell (x, y). A warp may target its own map.
   - `npcs`: npc id, cell, facing (a `Directions` term).
   - `zones`: kind (a `ZoneKinds` term), area rect.
   Use `MapObjectTypes` terms for the list names. Keep the record usable from `netstandard2.1` / C# 9 (no reflection-only APIs).
2. **`MapGrid`** (runtime type, in `Game.Shared`): built once from a `MapGridFile`. Holds the decoded flags in a flat array;
   `Width`, `Height`, `InBounds(x, y)`, `IsWalkable(x, y)`, `BlocksLos(x, y)` (out of bounds = not walkable, blocks LOS),
   and the object lists as read-only arrays. No allocation in the query methods. Immutable and thread-safe.
3. **Loading:** for each `MapDef`, read `content/maps/<GridFile>` (System.Text.Json, snake_case to match the YAML naming).
   `ContentDatabase` exposes the grid by map id (e.g. `Grids` or `GetGrid(mapId)`). A missing, unreadable or malformed grid,
   a wrong `map_id`, or `cells` whose decoded length ≠ `width * height` is a **load error** naming the grid file.
   `GridFile` must be a bare file name (no directories) — reject anything else.
4. **Validation rule** (`MapGridRule`, registered in `ContentValidator.DefaultRules`), each error naming the grid file and a path
   like `warps[2].target`:
   - unknown monster / npc / target map id (`ref.missing`, like the other reference errors)
   - a warp, warp target, or NPC on a non-walkable or out-of-bounds cell
   - a spawn or zone rect out of bounds, or a spawn rect with no walkable cell; count < 1; respawn < 0
   - unknown facing or zone kind; set flag bits that are not in `CellFlags`
   - two warps on the same cell
5. **Sample content:** a grid for `map.starter_meadow` (about 48×32: open meadow, a fence or rock line that blocks walking and LOS,
   a pond that blocks walking but not LOS, spawns for the existing sample monsters, both sample NPCs, one `safe` zone around them).
   Add one small second map (original name, its own `.yaml` + manifest keys) so there is a warp pair in each direction.
   Remove the "file does not exist yet" comment from `starter_meadow.yaml`.
6. **`grid` tool command:** `dotnet run --project src/Game.Tools -- grid from-ascii <in.txt> <out.grid.json>` turns an ASCII map
   plus a small header/legend into a grid file (e.g. `.` walkable, `#` blocks walk + LOS, `~` blocks walk only). Objects can come
   from a YAML/JSON sidecar or the header — your call, keep it simple and document it in `content/README.md`. Commit the ASCII
   sources next to the grids (e.g. `content/maps/src/*.txt`) so the samples can be regenerated; make sure the loader ignores them.
   This is a stopgap until T-208, say so in the command help.
7. **Tests:** sample maps load and validate clean; `MapGrid` decode (bit order, row-major, out of bounds); every validation error
   in 4 has a test against a temp copy of the content; malformed base64 / wrong length / wrong `map_id` / bad `format_version` are
   load errors; the `grid from-ascii` round trip.
