### Goal
A player ticks one or more active quests, and the server plays them in sequence: it travels to the right map, hunts, gathers, walks, talks and turns in, until each is done.

### Requirements
1. **It runs on the server** (rules 1 and 11): monster positions, spawns and routes never go to the client.
2. **It plays by the player's rules.** The autopilot decides, then queues the same intents a player would (`MoveTo`, `AttackTarget`, `UseSkill`, `PickUp`, `TalkTo`, `DialogueChoose`). Every existing check, range, cooldown and cost applies. It never grants, teleports or bypasses anything. Systems talk by events and intents only (rule 7).
3. **The queue.** The client sends the ticked quests in order, plus the skill ids (and levels) in its shortcut slots. The server checks that each quest is active, the skills are learned and active, and the counts are within limits; a refusal has a reason term. A finished quest moves on to the next, and the run ends when the list does. State follows the character through warps.
4. **Objectives.** Choose the current step's next unmet objective:
   - **`kill`:** on a map with the monster, attack the nearest living one that can be reached. Otherwise travel to the nearest map that has it.
   - **`collect`:** hunt the monsters that drop the item, and pick up that item only, under the normal loot-priority rules. Count what the bag already holds.
   - **`reach`:** walk to the cell.
   - **`talk`:** go to the NPC and talk. The turn-in is a talk, so this is also how a step ends.
   - **`level`, `job`, `equip`, `use_item`:** pause with a reason term. It never changes job, equips or consumes an item.
5. **Travel.** "Nearest" is the fewest warps, then the shortest walk, over the maps' warp graph. Handle an unreachable target, a warp that moves the character mid-plan, and a map change made by something else. Pathfinding stays within the existing limits and off a per-tick budget: say what one autopilot costs per tick, and what 100 cost together.
6. **Fighting.** Cast the shortcut skills in slot order when the server's own rules allow, else auto-attack. Use offensive skills on the target and supportive ones only on the player, and skip ground-targeted skills unless the effect is clearly offensive: document the rule. Don't drink potions. Retaliate against a monster that attacks while travelling only if it blocks the plan: document the choice.
7. **Dialogue.** Pick only choices that start or turn in a ticked quest, or plain "continue" nodes on the way to one. Never a service, reset, save point, item trade, or job change. If no safe choice exists, close the dialogue and pause.
8. **Stopping.** Manual input (move, stop, attack, skill, item, dialogue, shop, respawn), `logout`, disconnect (no play in the grace period), death, a full bag that blocks progress, and the fork's limits all stop it, with a reason. A resume does not restart it.
9. **Limits as data.** `balance.yaml` `autopilot`: enabled, the longest queue, a daily time limit (0 = none, the default), how long without progress before it pauses, plus anything else tunable. Validated, with schema. `enabled: false` refuses the intent.
10. **Wire.** An intent to start (with the list) and one to stop, and one status message (state, current quest, what it is doing as a term, pause reason): sent on change, never per tick. Terms go in VOCABULARY. No monster position or spawn data in it.
11. **Tests.** Each objective type; travel over one and two warps; unreachable; the queue in order; every stop reason; every refusal; skill order and cooldown; dialogue safety (an NPC offering both a quest and a service); rewards no different from manual play; a kill stolen by another player; two players on the same monster; determinism with the injected clock and RNG; the per-tick cost. One full-path test finishes First Hunt, from accept to turn-in, with no manual input after the start.
