Three small leftovers from T-403 and T-501, all on the theme side:
- a broken equipment manifest entry is caught at build time, not on screen;
- worn equipment is loaded before it's first needed, so putting gear on doesn't stall a frame;
- placeholder weapons look like their weapon type.

### Requirements
1. **Validation (row 182).**
   - Each `model.equip.*` manifest entry has exactly one of `attach` or `skinned`.
   - An `attach` bone exists in the theme's rig.
   - Every weapon-type clip suffix (`<animation id>.<weapon type>`) is a known weapon type from VOCABULARY.md.
   - Every item `visual_asset_key` in the display bundle resolves somewhere in the theme chain, or is reported as a warning that names the fallback.

   Each failure is an error with the file, key and reason. It runs in the same command CI already runs for themes, and it's covered by tests with broken fixtures.
2. **Preloading (row 182).** Load the models for worn visuals on screen, and for items in the own inventory, before they're needed. Use the same main-thread-when-headless and threaded-with-a-renderer rule (row 141) and the same shared cache. Keep a memory bound, and report the cost against §9. Show with a measurement that equipping an item already in the bag no longer stalls a frame: frame time at the moment of equipping, before and after.
3. **Placeholder weapon shapes (row 181).** `themegen` picks a placeholder weapon's shape by its weapon type: a dagger looks like a short blade, a staff like a staff, and so on, with original simple shapes. `themegen --check` stays clean, and the pack is regenerated with a byte-stable diff.
4. **Row 208.**

   - Fix the measure tool's "Cannot access a disposed object" in its breakdown step, if you can reproduce it; say if you can't.
5. **Tests.** Every validation rule with a broken fixture; preload selection (which keys, and the cache shared); weapon-type shape choice; the LFS pointer message.
