### Goal
NPCs stand in the world, and a player can walk up, talk, and click through a dialogue that the server drives.
- Map files already place NPCs and the client bundle carries the placements, but the server never spawns them.
- Dialogue graphs exist as data but nothing runs them.
- Choices can do things through generic, data-driven **dialogue actions**, which makes NPC services possible: set the save point, run effects such as a reset, and (row 187) host refining if you decide it moves behind an NPC.

Quests are **T-602**. This task raises the events quests will listen to, but doesn't run quests.

### Requirements
1. **NPC entities.** Each map instance spawns its grid's NPC placements as `EntityKind.Npc` entities on their cells and facing, with the AOI and the visible cap that already exist.
   - NPCs never move, can't be attacked or targeted by skills, and block their cell for pathing (decide; document it).
   - A missing `npc_id` is a load error (rule 5).
2. **Talking.**
   - `talk` (NPC entity) is refused unless the NPC is within a data-driven `dialogue.talk_range` (in `balance.yaml`), the player is alive and the NPC is in view. The player walks into range like an auto-attack, then the dialogue starts.
   - One dialogue per player at a time. Moving away beyond the range, a warp, death or disconnect ends it.
   - Raise `NpcTalked` (already in VOCABULARY) on the bus.
3. **Dialogue graph.**
   - The server holds the player's position in the graph and sends the current node: speaker, text, and the indices and texts of the choices that are shown.
   - `dialogue_choice` (index) moves on. A node with `next: null` and no choices ends the dialogue.
   - The client never decides where a choice goes.
   - Validate every graph at load: start node exists, every `next` exists, no unreachable nodes (a warning), every referenced id exists.
4. **Conditions and actions, as generic primitives (hard rule 2).** Add to choices (and nodes, if useful):
   - `conditions`, which decide whether a choice is shown: base or job level at least, job is or isn't, has an item and quantity, has a status. Quest-state conditions are added by T-602 on the same seam, so design the seam for it.
   - `actions`, which run in order when a choice is picked:
     - `start_quest` (raises `QuestStartRequested`; replaces `start_quest_id`, migrating the data);
     - `set_save_point` (this NPC's map and a cell from data);
     - `run_effects` (an effect list through T-501's runner, on the player);
     - `take_item` / `give_item` (atomic, hard rule 10, refused cleanly when the bag is full or the item is missing);
     - `open_service` (a service id the client opens, for example `refine`).

   Each type gets VOCABULARY entries and tests. Every refusal has a reason term.
5. **Services.**
   - **Save point:** `set_save_point` replaces "the respawn point of its map" (row 202) for `teleport to_save_point` and for respawn, if you decide death should use it. Document the rule.
   - **Refine:** decide whether `refine` moves behind an NPC (row 187). If it does, gate the existing `refine` intent on an open `refine` service from an NPC in range, and add a refining NPC to the starter meadow data; if not, record why.
   - **Resets:** add a choice that gives a free reset below level 10 through `run_effects`, reusing T-503's effects, so the service site row 234 mentions exists. Keep the reset items too.
6. **Client.**
   - Tap an NPC to talk: tap rules from T-401 row 174, with an NPC preferred over ground when tapped directly.
   - A dialogue panel with the speaker's name, title and portrait key (fallback per §7.7), the text, and the choices as touch targets of at least 48 dp.
   - A Close button, and the panel closes when the server ends the dialogue.
   - The client's own words go in `UiText`. Keep T-211's rules, the §9 budgets, and the T-222 look.
7. **Tests.**
   - NPC spawning and blocking;
   - talk range and every refusal;
   - graph walking with conditions shown and hidden;
   - every action type, with refusals and atomicity;
   - the save point used by teleport and respawn;
   - ending on move, warp, death and disconnect;
   - load validation of graphs;
   - the wire messages;
   - a scripted client run step: walk to Odalys, talk, pick a choice, see the next node, close.
