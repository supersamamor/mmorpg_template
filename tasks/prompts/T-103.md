### Goal
Formula strings from content compile once at load into fast, sandboxed evaluators that accept only whitelisted variables and functions.

### Scope — files you may create or change
- `src/Game.Shared/Formulas/**`
- `src/Game.Content/Validation/FormulaRule.cs`
- `tests/Game.Tests/Formulas/**`

### Out of scope — do not touch
- Stat pipeline and combat (T-104, T-106)

### Requirements
1. Pick an expression library (e.g. NCalc) or write a small Pratt parser. Justify the choice: needs ternary, comparison, arithmetic, function calls, no reflection or arbitrary method access.
2. Abstraction lives in Game.Shared: `IFormula { double Evaluate(IFormulaContext ctx); IReadOnlySet<string> Variables { get; } }`. If the library is a package, wrap it so Game.Shared stays dependency-light (put the implementation in Game.Content if necessary and inject).
3. Whitelist variables and functions from VOCABULARY.md. Unknown identifiers are **load-time** errors via a validation rule.
4. Constants-only formulas (e.g. `"17"`) must be cheap.
5. Deterministic: no RNG inside formulas. Chance formulas return a probability; the caller rolls with injected `IRandom`.
6. Tests: arithmetic, ternary, functions, unknown variable rejected, division by zero behavior defined and documented, performance sanity (1M evaluations of a typical damage formula under ~1s in Release).

- [ ] `dotnet test` passes
