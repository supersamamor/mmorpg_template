### Goal
A small, coherent, **original** starter game in `/content` that exercises every definition type. It is the fixture for all Phase 1 tests and the reference for future content.

### Scope — files you may create or change
- `content/**`
- `themes/default/asset-manifest.json` (keys only; files may be placeholders)

### Out of scope — do not touch
- Any C# code
- Ragnarok names, item names, monster names, or numbers — invent your own

### Requirements
1. Folder per type: `jobs/`, `skills/`, `items/`, `monsters/`, `statuses/`, `quests/`, `npcs/`, `dialogue/`, `drops/`, `maps/` (metadata only), plus `formulas.yaml`, `elements.yaml`, `exp_tables.yaml`, `balance.yaml`.
2. Minimum: 3 jobs (novice + 2 first jobs), 6 skills, 12 items (potions, 2 weapon types, armor, 1 card, materials), 5 monsters (levels 1–10, 2 elements), 3 statuses, 2 drop tables per monster tier, 1 NPC with dialogue, 1 quest (kill + talk), 1 map metadata file.
3. `formulas.yaml`: derived stats (max_hp, max_sp, atk, matk, def, mdef, hit, flee, crit, aspd, move_speed in cells/second), physical & magic damage, hit chance, crit chance. Only whitelisted variables from VOCABULARY.md.
4. `exp_tables.yaml`: base levels 1–99 and job levels 1–50 using a formula-generated curve; include the generator expression as a comment.
5. Every file starts with `# yaml-language-server: $schema=../../schemas/<type>.schema.json` (adjust path).
6. Every asset key referenced exists in `asset-manifest.json`. Use the 3D key prefixes from VOCABULARY.md (`model.`, `anim.`, `scene.`, `icon.`, …). Point files at placeholders for now: `placeholder.glb` for models/anims, `placeholder.tscn` for scenes, `placeholder.png` for icons/UI; give models a `rig` and equipment `attach`/`skinned` per ARCHITECTURE §8.
   The map metadata names a grid file that does not exist yet (the exporter comes in T-208); that is expected.
7. Add `content/README.md` explaining folder conventions.
