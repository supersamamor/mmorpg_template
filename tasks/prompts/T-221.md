### Goal
Godot's headless tooling steps sometimes hang and nothing notices. In Phase 4:
- `--import` hung in about 1 of 4 imports, at almost no CPU. Twice it stalled a run for about 7 hours, once in `run-e2e.ps1` and once in `export-maps.ps1`.
- The release export hung at exit 2 times in 3 tries, after writing every file.
- `run-e2e.ps1` once kept waiting after a client had passed and exited, until its server was stopped.

Make every Godot step bounded and retried, and find out why it hangs.

### Requirements
1. **One helper.** A single function, in `godot-path.ps1`, that every script uses to run a headless Godot step (import, export, map export). It needs:
   - a time limit per kind of step, as parameters with sensible defaults;
   - a check for "the expected output is complete" (for example, files written or the import cache stamped), with a shorter wait for Godot to exit after that;
   - stopping the whole process tree on a timeout, by process id and never by name (the console wrapper and its child, ADR-002 row 166);
   - a bounded number of retries, a clear one-line log for each attempt (step, attempt, seconds, outcome) and a non-zero exit when the retries run out.

   No step may wait without a limit.
2. **Harness waits.** Every wait in `run-e2e.ps1` is bounded, including the one in row 190, where the client had exited but the script kept waiting. Find out why it happened and fix it. A run never waits longer than its declared limit.
3. **Find the cause.** Reproduce the import hang and the export hang at exit, measure how often each happens, and collect evidence, for example:
   - Godot's `--verbose` log;
   - a thread dump or minidump of the hung process (`procdump` if it's available, or `dotnet-dump`/WinDbg-free alternatives);
   - whether the theme junction, the .NET build step, or parallel Godot processes from other worktrees matter.

   T-218 found a similar engine bug (row 141), so check whether this is related. If it's an engine bug you can't fix, give a minimal reproduction and the evidence, keep the retry as the workaround, and say what risk remains. Don't claim a fix you haven't shown.
4. **CI.** Give each Godot step in `ci.yml` a `timeout-minutes` that matches the new limits. That job has never run on GitHub; say so.
5. **Proof.** Run the import 30 times and the release export 20 times through the new helper, and report the counts: clean, recovered by retry, and failed. Run `client/run-e2e.ps1 -Run all -Port 7818` and `client/export-maps.ps1 -Check` three times each.
