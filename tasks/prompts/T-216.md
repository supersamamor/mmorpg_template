### Requirements
1. **No plaintext outside debug.** A pure rule in `client/Core`, with tests: a release build refuses any `ws://` URL with a clear screen; a debug build allows it. Add Android's network-security config and the iOS ATS settings §10 describes. A settings file edited after install can't re-enable it in release.
2. **Strip the APK.** Remove libraries and architectures the client doesn't use (arm64-v8a only, §7.1). Report what was removed and the APK size before → after. T-206 measured 104.2 MB, 178.5 MB uncompressed. Confirm the export still contains the bundle and settings. Keep whatever T-005 proved necessary.
3. **CI export job.** A job with a hard timeout: installs the pinned Godot and templates (cached), builds the client, exports an Android debug APK and runs the headless `client/run-e2e.ps1`. Keep it separate from the fast job, so that a slow export doesn't block the server checks. Pin every version as MOBILE_BUILD does.
4. **Framework.** Check whether the pinned Godot supports .NET 10. If it doesn't, record that in MOBILE_BUILD and change nothing.
5. **Live `bye` tests (row 122).** Extend `run-e2e.ps1` with live runs against the Godot socket for `replaced`, `resume_failed` and `shutdown`, plus grace-period expiry, which T-206 only covered by unit tests. Report any behaviour that differs from §10.
6. **Load-test option (row 122).** A `tools/loadtest` option for extra session slots, so a client can join a bot-filled server without a throwaway launcher.
