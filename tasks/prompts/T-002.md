### Goal
Immutable C# records for every content definition type listed in ARCHITECTURE.md §5.2, plus enums/constants for everything in VOCABULARY.md. These records are the contract that YAML, schemas, the validator, and every system build on.

### Scope — files you may create or change
- `src/Game.Shared/Definitions/**`
- `src/Game.Shared/Vocabulary/**`
- `tests/Game.Tests/Definitions/**`

### Out of scope — do not touch
- Loading/parsing YAML (T-101)
- Any game logic, formulas, or calculations

### Requirements
1. Records (`sealed record`, `init` props, `IReadOnlyList`/`IReadOnlyDictionary` collections): `JobDef`, `SkillDef`, `ItemDef`, `MonsterDef`, `StatusDef`, `QuestDef`, `NpcDef`, `DialogueDef`, `DropTableDef`, `MapDef`, `ExpTableDef`, `ElementTableDef`, and a root `FormulaSetDef` for `formulas.yaml`.
2. Every def has `string Id` and `string Name` (except tables where Name is optional). Ids are plain strings; add a static `IdPrefix` per type (e.g. `ItemDef.IdPrefix = "item."`).
3. Model `ItemDef` with a `Kind` enum and optional sub-blocks (`Equip`, `Consumable`, `Card`) rather than inheritance — keeps YAML flat and schemas simple.
4. Effects: `EffectDef` with `Type` (string, must be one of VOCABULARY effect types) and a typed parameter bag for v1 types. Prefer a discriminated set of records (`DamageEffect`, `HealEffect`, …) with a `Type` discriminator usable by both YamlDotNet and System.Text.Json.
5. Modifiers: `ModifierDef(string Stat, ModifierOp Op, string Value)` — `Value` is a formula string so it can be constant or level-scaled.
6. Quest objectives and rewards use the same discriminator approach as effects.
7. Asset references are strings named `...AssetKey` (e.g. `ModelAssetKey`, `IconAssetKey`, `SceneAssetKey`). Never file paths. Equipment carries a `VisualAssetKey` (a `model.*` key; the manifest says skinned vs attached — ARCHITECTURE §7.5). `MapDef` holds metadata only: `SceneAssetKey`, `MusicAssetKey`, and the logic grid file name (ARCHITECTURE §5.3); the grid itself is not a def.
8. Put all VOCABULARY lists in `Vocabulary/*.cs` as `static class` string constants **and** a `static IReadOnlySet<string> All` per category, so the validator can check membership. Stats/elements/slots may be enums if you prefer — explain the choice.
9. XML doc comments on every public type and property — they become schema descriptions in T-003.
10. Tests: construct one of each def in code; assert vocabulary sets contain the documented values.
